# Tools

What the six services behind the gateway are, and where each request goes.

The UI stores these addresses in its admin screen and calls them from its own
tool implementations. When to use a tool, and which agent may use it, is decided
by the UI — this document covers only what the backend provides.

## Paths and the calls behind them

The gateway strips the prefix and forwards to each service's root. The UI stores
everything up to the prefix as a base URL and appends the service-specific path.

| Capability | Base URL | What the UI actually calls | Service |
|---|---|---|---|
| Models | `/litellm` | `/litellm/v1/chat/completions`, `/litellm/key/generate` | LiteLLM |
| Web search | `/tools/search` | `/tools/search/search?q=…&format=json` | SearXNG |
| Document fetch | `/tools/fetch` | `/tools/fetch/v1/scrape` | crawl4ai-shim |
| Code execution | `/tools/exec` | `/tools/exec/exec` | code-interpreter |
| Deep research | `/tools/research` | `/tools/research/mcp` | deep-research |
| Transcription | `/tools/stt` | `/tools/stt/v1/audio/transcriptions` | whisper-shim |
| Retrieval index | `/tools/index` | `/tools/index/{documents,search}` | index-shim |

The contract is identical without the gateway, so a raw service address works
too.

LiteLLM is exposed at its service root because its admin API (`/key/*`,
`/user/*`, `/model/info`, `/health/*`) does not live under `/v1`. `/v1/*` is
also open, for OpenAI-compatible clients that connect directly.

## Authentication

Only `/litellm/*` and `/v1/*` pass the caller's `Authorization` header through —
the UI calls with a per-user LiteLLM virtual key, so spend is attributed to a
person.

`/tools/*` is not authenticated. The internal keys for code execution and
document fetching are injected by the gateway, so the UI never learns them and
caller-supplied credentials are ignored. **The gateway port must only be open
inside a private network** — a sandbox that runs arbitrary code sits behind it.

## Services

### Web search — SearXNG

A metasearch front end, so queries never reach a commercial search API. Worker
state is shared through valkey and may be empty after a restart. Configuration is
`services/searxng/settings.yml`, generated by `scripts/gen-searxng-config.sh`
from `SEARXNG_SECRET_KEY` in `.env`.

### Document fetch — crawl4ai-shim

A Firecrawl-compatible `/v1/scrape` in front of Crawl4AI. The image is large
because it carries Playwright and Chromium; in exchange, pages that need
rendering still come back as markdown body text.

### Code execution — code-interpreter

Sandboxed Python. This is the only service with `SYS_ADMIN` and relaxed
apparmor/seccomp, which is what lets user code run at all. Execution is capped at
30 seconds and 512 MB. Output files are stored in MinIO, though today the UI
reads only stdout and stderr.

The image bundles NanumGothic and sets it as the matplotlib default so that
Korean chart labels render.

### Deep research — deep-research

`local-deep-research` wrapped by `mcp-proxy` into an MCP streamable-http server.
It searches through the SearXNG on the same network and calls models through the
LiteLLM on the same network. A single call takes minutes to tens of minutes.

The UI attaches it as an HTTP MCP connector; the tool list and calling
convention are defined by MCP. Internals are in
[internal/deep-research.md](internal/deep-research.md).

### Transcription — whisper-shim

A front end for faster-whisper on the GPU nodes. Backends live on the same nodes
as vLLM (amd64 only), and `WHISPER_URLS` lists **only the backends that
answered** a probe during placement. With several nodes it routes by in-flight
count.

Without a backend the shim's `/health` reports `degraded`, so it is fenced behind
the `whisper` profile and never started alone: `setup.sh` enables that profile
once `WHISPER_URLS` is populated. When it is empty — an arm64-only cluster, or no
GPU at all — LiteLLM registers OpenRouter STT instead of the shim.

### Models — LiteLLM

The single point for every model call. Local vLLM and OpenRouter are registered
under the same names, so a model whose local node is missing or down goes out to
OpenRouter unchanged. Configuration is `services/litellm/config.yaml`, generated
by `scripts/gen-litellm-config.sh` from the `VLLM_*_URL` values and the
OpenRouter key in `.env`.

## Checking status

```bash
./scripts/setup.sh urls
```

It prints whether each capability is actually reachable through the gateway.
`not started` means that service's container is not running — check
`COMPOSE_PROFILES` first.
